# mmnote(メンテナンス手帳)

車両や機械・設備のメンテナンス記録を残す、スマートフォン向けの Web アプリです。機器ごとに型番・仕様・写真を登録し、点検や修理の記録と次回の予定日を書いておくと、期限切れや期限が近い予定を画面で確かめられます。データはすべて端末のブラウザの中に保存し、サーバーへは送りません。写真を含む全データを ZIP ファイルに書き出し、読み込んで戻せます。

公開 URL: https://4each-biz.github.io/mmnote/

## 機能

画面下のタブは「機器」「予定」「記録」「設定」の 4 つです。

- 機器
  - 名称、種別(車両 / 機械 / 設備 / その他)、メーカー、型番、製造番号、導入日、仕様(項目と値の組を 30 行まで)、メモ、写真を登録します。
  - 一覧では、名称・メーカー・型番・製造番号・メモ・仕様で検索し、種別で絞り込み、名称順 / 期限が近い順 / 更新が新しい順に並べ替えられます。期限切れや期限間近の予定はバッジで示します。
  - 詳細には、写真、基本情報、次回予定、仕様、メモ、記録の履歴を出します。
- 写真
  - 機器と記録に 10 枚ずつ付けられます。スマートフォンではカメラで撮るか写真ライブラリから選べます。入力シートの中でも、詳細画面からでも追加できます。
  - 長辺 1600px までの JPEG に縮小して保存します。表示用のサムネイル(長辺 320px まで)も作ります。
  - 詳細画面の写真はタップで拡大表示し、そこから削除できます。機器の写真は「表紙にする」で一覧に出す 1 枚を選べます。
- 記録
  - 実施日、区分(点検 / 修理 / 交換 / 清掃 / その他)、作業内容、費用、作業者・業者、計器の値と単位(`km`、`h` など)、次回予定日、メモ、写真を書きます。
  - 次回予定日は「1 か月後 / 3 か月後 / 6 か月後 / 1 年後」のボタンで、実施日を起点に埋められます(月末は月の最終日に丸めます)。
  - 記録タブでは全機器の記録を新しい順に並べ、月ごとに費用の合計を出します。区分と機器で絞り込み、作業内容・業者・メモで検索できます。
- 予定
  - 機器ごと・区分ごとに、実施日がいちばん新しい記録の次回予定日を「生きている予定」とします。同じ区分で実施日がより新しい記録を書けば、前の予定は済んだことになります。その記録の次回予定日が空なら、その区分の予定は無くなります。
  - 予定タブでは全機器の予定を日付順に並べ、「期限切れ」「期限間近」「それ以降」に分けます。行の「実施を記録」から、機器・区分・作業内容を引き継いだ記録を書けます。
  - 期限切れの件数をタブに出します。通知(プッシュやメール)はしません。
- 設定
  - 表示: テーマ、拡大率、言語、期限間近の日数、通貨記号
  - データ: エクスポート、インポート、サンプルデータを入れる、すべてのデータを消去、保存量の目安
  - サポート: サポートページへのリンク
  - About: バージョン、リポジトリ、ライセンス、クレジット
- 画面右上のボタン: ヘルプ(マニュアルを別のタブで開く)、ダーク / ライトの切り替え、縮小、拡大、日本語 / 英語の切り替え。10 秒操作しないとボタンが薄くなります。
- 画面下の帯に、機器と記録の件数、直前の操作の結果、状態(緑 = 正常 / 黄 = 注意 / 赤 = 失敗)を出します。
- PC でも開けます。幅の広い画面では、中央寄せの 1 列で表示します。

## 使い方

1. 公開 URL をスマートフォンのブラウザで開きます。
2. ホーム画面に追加すると、アプリのように全画面で開けます。
   - iPhone / iPad(Safari): 共有ボタン →「ホーム画面に追加」
   - Android(Chrome): メニュー →「ホーム画面に追加」または「アプリをインストール」
3. 機器タブの右下の追加ボタンで機器を登録します。
4. 機器の詳細の「記録」の追加ボタンで記録を書きます。次の点検日などがあれば次回予定日に入れます。
5. 予定タブで期限切れ・期限間近の予定を確かめます。

試しに触るときは、設定タブの「データ」にある「サンプルデータを入れる」で、機器 4 件と記録 15 件を入れられます(データが 1 件も無いときだけ押せます)。サンプルの日付は今日を基準に作るので、期限切れ・期限間近・それ以降の予定がそれぞれ出ます。

## 設定項目と URL パラメータ

| キー | 値 | 既定値 | 内容 |
|---|---|---|---|
| `theme` | `auto` / `light` / `dark` | `auto` | 配色。`auto` は端末の設定に合わせます |
| `zoom` | 50〜200(10 刻み) | `100` | 拡大率(%)。範囲外は 50 か 200 に、刻みに合わない値は近い 10 の倍数に丸めます |
| `lang` | `ja` / `en` | ブラウザの言語が日本語なら `ja`、それ以外は `en` | 表示の言語 |
| `dueSoonDays` | 1〜180 の整数 | `30` | 予定日の何日前から「期限間近」とするか |
| `currency` | 4 文字までの文字列 | `¥` | 費用の前に付ける記号 |

設定タブや画面右上のボタンで変えた値は、ブラウザの localStorage(キー `mmnote`)に保存します。

同じキーを URL パラメータでも指定できます。優先順位は URL パラメータ > 保存した設定 > 既定値です。正しくない値は無視します。

- URL パラメータの値は、そのままでは保存しません。`save=1` を付けたときだけ保存します。ただし、開いたあとで設定を変えると、そのとき画面に効いている設定がまとめて保存されます。
- `tab` で、最初に開くタブを指定できます(`equipment` / `dues` / `records` / `settings`。保存はしません)。

例:

```
https://4each-biz.github.io/mmnote/?theme=dark&lang=en
https://4each-biz.github.io/mmnote/?tab=dues&dueSoonDays=14&save=1
```

## データの保存先と注意

- データは、開いている端末のブラウザの中(IndexedDB の `mmnote`)にだけ保存します。サーバーへは送らず、ほかの端末と同期もしません。
- ブラウザのサイトデータを消すと、データも消えます。
- iPhone / iPad では、ホーム画面に追加したアプリとブラウザ(Safari)で保存場所が別になります。また、しばらく開かないとデータが消されることがあります。
- 端末の故障や機種変更に備えて、設定タブの「エクスポート」で定期的に ZIP ファイルに書き出してください。
- 起動時に、ブラウザへ保存領域の永続化を求めます(`navigator.storage.persist()`)。認められるかどうかはブラウザによります。

## エクスポートの ZIP の形

ファイル名は `mmnote-YYYYMMDD-HHmm.zip`(書き出した時刻)です。

```
data.json
photos/<写真の id>.jpg
```

- `data.json` は圧縮し、写真(JPEG)は無圧縮で入れます。サムネイルは入れず、インポートのときに作り直します。
- `data.json` の形:

```json
{
  "app": "mmnote",
  "version": 1,
  "exportedAt": "2026-11-21T09:00:00.000Z",
  "settings": { "theme": "auto", "zoom": 100, "lang": "ja", "dueSoonDays": 30, "currency": "¥" },
  "equipment": [],
  "records": [],
  "photos": [
    { "id": "…", "ownerType": "equipment", "ownerId": "…", "file": "photos/….jpg", "width": 1600, "height": 1200, "createdAt": "…" }
  ]
}
```

- `equipment` の各要素: `id`、`name`、`category`、`maker`、`model`、`serial`、`acquiredOn`(`YYYY-MM-DD` または `null`)、`specs`(`{ "label", "value" }` の配列)、`note`、`photoIds`(並び順。先頭が表紙)、`createdAt`、`updatedAt`
- `records` の各要素: `id`、`equipmentId`、`date`(`YYYY-MM-DD`)、`kind`(`inspection` / `repair` / `replacement` / `cleaning` / `other`)、`title`、`cost`(0 以上の整数または `null`)、`vendor`、`meterValue`(0 以上の数または `null`)、`meterUnit`、`nextDue`(`YYYY-MM-DD` または `null`)、`note`、`photoIds`、`createdAt`、`updatedAt`
- `photos` の `ownerType` は `equipment` か `record` です。

インポートは全置き換えです。今のデータはすべて消え、ZIP の中身に入れ替わります(設定も ZIP のものになります)。確認の画面で件数を示してから行います。

- `app` が `mmnote` でない、`version` が `1` でない、`data.json` が無い・読めない場合は中止し、今のデータは変えません。
- 必須の項目が無いデータ、機器の無い記録、ZIP にファイルの無い写真、持ち主の無い写真、読めない画像は捨てて取り込み、捨てた件数を知らせます。

## サポートのリンク先の差し替え

ヘルプボタンと設定タブの「サポート」のリンク先は、`index.html` の中の定数 `SUPPORT`(`<script id="app-logic">` の中)の 1 か所で決めています。

```js
const SUPPORT = {
  base: 'https://support.trusted-host.online/t/mmnote',
  links: [
    { key: 'manual',   path: '/manual' },
    { key: 'faq',      path: '/faq' },
    // …
  ],
};
```

自分のサポートページに向けるときは `SUPPORT.base` を書き換えます。各リンクは `base` に `path` をつないだ URL を別のタブで開きます。アプリからサポートページへの通信はしません。

## 開発

ビルドはありません。リポジトリの中身を静的に配信すれば動きます。外部の CDN やフォントは読み込みません。

- ローカルでの起動: リポジトリの直下で静的ファイルのサーバーを起動し、ブラウザで開きます。

```bash
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

- テスト: Node.js 20 以上で、追加のパッケージは要りません。

```bash
node --test test/*.test.mjs
```

テストは `index.html` の `<script id="app-logic">`(画面や保存に触らない処理をまとめた `Logic`)を切り出して確かめます。画面の操作、IndexedDB、画像の縮小、ZIP の読み書きはブラウザで動かして確かめます。

ファイルの構成:

```
index.html             アプリ本体(HTML・CSS・JavaScript)
manifest.webmanifest   ホーム画面に追加するための設定
icons/                 アイコン
vendor/fflate.js       ZIP の読み書きに使うライブラリ
test/                  Logic のテスト
docs/                  設計書と実装計画
```
