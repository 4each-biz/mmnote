# メンテナンス手帳 (mmnote) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 車両・機器の台帳とメンテナンス記録(次回予定つき)を、index.html 1 ファイルのスマートフォン向けアプリとして作り、GitHub Pages で公開できる状態にする。

**Architecture:** ビルドなしの `index.html` に、DOM に触らない純粋関数の `Logic`(`<script id="app-logic">`)と、DOM・IndexedDB・画像・ZIP を扱う `App`(`<script id="app-ui">`)を置く。設定は localStorage、機器・記録・写真は IndexedDB。`Logic` は `node --test` で TDD、`App` はブラウザで実際に動かして確認する。

**Tech Stack:** 素の HTML / CSS / JavaScript(ES2020)、IndexedDB、Canvas、fflate 0.8.3(同梱)、Node.js 20 以上の `node:test`。

**Spec:** `docs/superpowers/specs/2026-11-21-mmnote-design.md`(作業者は必ず両方を読む。画面の中身・データ項目・判定規則は設計書が正)

## Global Constraints

- 作りの手本にした既存プロジェクトの名称は、コード・コメント・文書・保存キー・コミットメッセージのどこにも出さない。名称は本書に書かない。作業者は依頼者から受け取った名称を環境変数 `ORIGIN_NAME` に入れ、**各タスクのコミット前に** `git grep -n -i -e "$ORIGIN_NAME" ; git log --format=%B | grep -i -e "$ORIGIN_NAME"` を実行し、どちらも 0 件であることを確かめる。手本の骨格(ツールバー、シート、タブ、テーマ、拡縮、i18n、テストヘルパー)は読んで写してよい。
- 外部読込なし(CDN、外部フォント、外部スクリプト)。読み込むのは `vendor/fflate.js`、`manifest.webmanifest`、`icons/` だけ。実行時に `fetch` / `XMLHttpRequest` を使わない。
- グローバルは `Logic`、`App`、`fflate` の 3 つだけ。`Logic` は DOM・IndexedDB・`Date.now()`・`new Date()`(引数なし)に触らない。「今日」「今」は引数で受け取る。
- 文字列の挿入は `textContent`。`innerHTML` は使わない。
- 太字(`font-weight` 600 以上、`<b>`、`<strong>`)と絵文字を UI に使わない。アイコンはインライン SVG の `<symbol>`。
- UI 文字列はすべて `Logic.I18N` の `ja` / `en` から出す。
- パスはすべて相対(`https://4each-biz.github.io/mmnote/` のサブパスで動くこと)。
- タップ対象は 44px 以上。`input` / `select` / `textarea` は `font-size: max(16px, …)`。
- 保存キー: localStorage は `mmnote`、IndexedDB は `mmnote`(version 1、ストア `equipment` / `records` / `photos` / `thumbs`)。
- 日付は端末のローカル時刻の `YYYY-MM-DD` 文字列で扱う(UTC に直さない)。
- テストは `node --test test/*.test.mjs`。ネットワークに依存させない。
- 作業は `build/app` ブランチで行う。`git push` と GitHub Pages の有効化は、依頼者の確認を得てから行う(Task 11)。

## Review Focus

仕様が明示していないが、使う人が踏みそうな入力と状況。それぞれのテストは担当タスクに入れてある。

1. **手で作った・壊れた ZIP の取り込み**: `photos` の `file` が `photos/<id>.jpg` の形でない(`../` を含む、別の id を指す)、同じ id が重複する、`equipment` が配列でない。期待: その項目だけ捨てて件数に数える。形そのものが違えば中止する。→ Task 9
2. **日付の境界**: 2 月 29 日の 1 年後、1 月 31 日の 1 か月後、深夜 0 時前後の「今日」(ローカル日付であること)、次回予定日が実施日より前。期待: 月末に丸める。ローカル日付で判定する。予定日が実施日より前なら入力エラー。→ Task 2、Task 3
3. **機器を消したあとの残り**: 消した機器の記録・写真・予定が一覧や絞り込みに残る。期待: 記録と写真もまとめて消え、絞り込みの選択も外れる。→ Task 3(`cascadeDelete`)、Task 7
4. **極端な文字列**: 空白だけの名称、上限を超える長さ、`<img onerror=…>` のような文字列、費用に負数・小数・文字。期待: 空白だけは必須エラー、長すぎるものは入力エラー(取り込み時は切り詰め)、タグは文字として表示、費用は 0 以上の整数だけ。→ Task 2、Task 5
5. **画像と保存の失敗**: 読めない画像(HEIC を読めないブラウザ、壊れたファイル)、0px の画像、容量超過、別タブで開いたままの DB 更新。期待: その画像だけ飛ばして件数を知らせる。保存失敗時はシートを閉じず入力を残す。→ Task 6(`fitSize` のテストと手動確認)、Task 5

  - `render()`(現在のタブと `view` を描き直す。シートが開いているあいだは何もしない)

### Task 3: 日付・期限・連鎖削除(Logic)

**Files:**
- Modify: `index.html`(`app-logic`)
- Test: `test/dates.test.mjs`

**Interfaces:**
- Consumes: Task 2 の `KINDS`、記録の形
- Produces:
  - `Logic.toDateStr(date: Date) -> 'YYYY-MM-DD'`(ローカルの年月日)
  - `Logic.addMonths(dateStr, n) -> dateStr`(同じ日が無ければその月の最終日)
  - `Logic.diffDays(fromStr, toStr) -> number`(`to - from` の日数)
  - `Logic.activeDues(records) -> Array<{ equipmentId, kind, nextDue, recordId, title }>`(機器 × 区分ごとに、`date` が最も新しい記録。同日は `createdAt` が新しいほう。その記録に `nextDue` があるものだけ)
  - `Logic.dueStatus(nextDue, today, dueSoonDays) -> 'overdue' | 'soon' | 'later'`
  - `Logic.listDues(records, equipment, today, dueSoonDays) -> Array<due & { status, days, equipmentName }>`(`nextDue` の昇順、同日は機器名順。機器が存在しない予定は除く。`days` は `diffDays(today, nextDue)`)
  - `Logic.equipmentBadge(equipmentId, dues) -> due | null`(`listDues` の結果から、その機器の最も早いもの。`status` が `later` なら null)
  - `Logic.cascadeDelete(equipmentId, equipment, records) -> { recordIds: string[], photoIds: string[] }`(機器の写真と、その機器の記録の写真をすべて含む)

- `obj.app !== 'mmnote'` → `err_import_not_mmnote`。`obj.version !== 1` → `err_import_version`。`equipment` / `records` / `photos` のどれかが配列でない → `err_import_shape`
- `settings` は `mergeSettings(DEFAULT_SETTINGS, obj.settings)`(オブジェクトでなければ既定値)
- 機器・記録・写真は正規化し、null は捨てる。id が重複したら後のものを捨てる
- 機器の無い記録は捨てる。持ち主(機器か記録)の無い写真は捨てる
- 写真の `file` が `'photos/' + id + '.jpg'` と完全に一致しない、または `fileNames` に無ければ捨てる
- 機器・記録の `photoIds` から、残らなかった写真の id を外す。どの `photoIds` にも入っていない写真は捨てる
- `dropped` は種類ごとの捨てた件数
