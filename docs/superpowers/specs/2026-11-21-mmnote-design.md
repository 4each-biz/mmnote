# メンテナンス手帳 (mmnote) 設計書

作成: 2026-11-21

## 1. 目的

mmnote は、サポート情報管理サービス system-support の機能を説明するための題材になるアプリ。

- note の紹介記事で画面を見せる
- マニュアルや紹介資料の題材にする(リポジトリは公開する: `https://github.com/4each-biz/mmnote`)
- 見せ場は「アプリのリポジトリから、system-support 上のサポート文書(マニュアル / FAQ / 規約 / リリースノート)を自動生成する」こと。これは mmnote が一通り完成してから行う別の作業で、本書の範囲には入れない

そのため mmnote 自体は、実際に使える小さなアプリであり、かつ説明する題材が十分にあること(少なすぎない機能)が求められる。

## 2. ゴール / やらないこと

### ゴール

- 車両・機器の型番・仕様・写真を登録できる
- 機器ごとにメンテナンス記録を残し、履歴を見られる
- 記録に次回予定日を持たせ、期限切れ・期限間近を画面で示す
- 写真を含む全データを ZIP で書き出し、読み込める
- system-support の公開ページ(`https://support.trusted-host.online/t/mmnote`)へのリンクを別タブで開ける
- スマートフォンの縦持ちで、現場でそのまま使える。ホーム画面に追加できる
- サンプルデータを 1 操作で入れられる(記事のスクリーンショット用)

### やらないこと

- サーバー、ログイン、端末間の同期、複数人での共有
- 通知(プッシュ、メール)。期限は画面の表示だけ
- 走行距離・稼働時間を基準にした期限
- 周期を登録する「定期項目」の管理
- system-support の API 呼び出し(問い合わせ投稿、エラー報告の自動送信、ステータス表示、埋め込み表示)。すべてリンクだけ
- Service Worker、オフライン起動
- PC 向けの 2 ペインレイアウト(PC でも開けるが、幅は中央寄せの 1 カラム)

### あってはならないこと

- 作りの手本にした既存プロジェクトの名称・参照が、コード・コメント・文書・保存キー・コミットメッセージのどこかに出ること。その名称は本書にも実装計画にも書かない(依頼者が作業者に直接伝える)。作業者は手本の骨格を読んで写してよいが、コミットの前に毎回、その名称と保存キーの接頭辞がリポジトリ全体に無いことを検索で確かめる
- 実行時に外部へ通信すること(リンクを別タブで開くのは利用者の操作なので別)
- 説明用サンプルとして読みにくくなる複雑さ(レイアウトの 2 系統化、汎用化のしすぎ)

## 3. 検討した方法

### 3.1 端末

| 案 | 内容 | 判断 |
|---|---|---|
| スマートフォン向け | 縦持ち、下部タブ、入力は下からのシート | **採用**。機器の前で写真を撮って記録する使い方に合い、コードも単純 |
| PC 向け | 一覧と詳細の 2 ペイン | 不採用。記事には載せやすいが手帳らしさが薄い |
| 両対応 | 幅で切り替え | 不採用。1 ファイルにレイアウトが 2 系統になり読みにくい |

### 3.2 次回予定の持ち方

| 案 | 内容 | 判断 |
|---|---|---|
| A. 記録に次回予定日を持たせる | 記録を書くときに任意で次回予定日を入れる | **採用**。画面が増えず、「記録を書く → 次回が決まる」という流れのまま |
| B. 機器ごとに定期項目を登録 | 「オイル交換 / 6 か月ごと」を登録し記録をひも付ける | 不採用。登録画面とひも付けが増え、サンプルとして重い |
| C. A + 計器値での期限 | 走行距離などでも期限を持つ | 不採用。複雑さの割に題材として得るものが少ない |

### 3.3 データの持ち出し

| 案 | 内容 | 判断 |
|---|---|---|
| ア. JSON に写真を base64 で埋め込む | 1 ファイルで完結、追加の仕組みなし | 不採用 |
| イ. ZIP(data.json + photos/) | 中身が扱いやすい。ZIP の読み書きが要る | **採用**。ZIP は外部ライブラリを同梱して使う |

保存先は IndexedDB(写真が localStorage の容量に収まらないため)。

## 4. 構成

### 4.1 ファイル

```
index.html                 アプリ本体
manifest.webmanifest       PWA
icons/                     icon-192.png / icon-512.png(maskable 兼用)/ apple-touch-icon.png(180px)
vendor/fflate.js       ZIP ライブラリ(MIT)。vendor/fflate.LICENSE を並べる
test/*.test.mjs            Logic のテスト
test/load-logic.mjs        index.html から app-logic を切り出して評価するヘルパー
README.md                  機能、設定項目、URL パラメータ、データ形式、ライセンス
LICENSE                    MIT
docs/                      本書など
```

- ビルドなし。`index.html` を静的に配信すれば動く。
- 外部読込(CDN、外部ドメインのフォント・スクリプト・スタイル)は持たない。読み込むのは同じリポジトリ内の `vendor/fflate.js`、`manifest.webmanifest`、`icons/` だけ。`src` / `href` に入れるパスは index.html 内に直接書いたものに限り、設定値や URL クエリを渡さない。
- 配信は GitHub Pages(`https://4each-biz.github.io/mmnote/`、main ブランチの直下)。パスはすべて相対で書き、サブパス配下でも動くようにする。スマートフォン実機での確認(ホーム画面への追加、保存の永続化)はこの URL で行う。push と Pages の有効化は外向きの操作なので、実行の前に依頼者へ確認する。
- `docs/`(本書と実装計画)は公開リポジトリにそのまま含める。
- 書体はシステムフォントスタック(`system-ui, -apple-system, "Segoe UI", Roboto, "Hiragino Sans", "Noto Sans JP", sans-serif`)。

### 4.2 スクリプトの分け方

`<body>` 末尾に、`<script src="vendor/fflate.js">`、`<script id="app-logic">`、`<script id="app-ui">` の順で置く。

- `app-logic`: DOM・IndexedDB・時刻の取得に触らない純粋関数。`Logic` を公開。テスト対象。
  - 設定のマージと検証、データの正規化、期限の判定、一覧の絞り込みと並べ替え、エクスポート用オブジェクトの組み立て、インポートの検証、i18n 辞書と `Logic.t(lang, key, params)`、サンプルデータの定義
  - 「今日」は引数で受け取る
- `app-ui`: DOM、IndexedDB、画像の縮小、ZIP、localStorage、タイマー。`App` を公開。
- グローバルは `Logic`、`App`、`fflate` の 3 つだけ。それぞれ IIFE に閉じる。

### 4.3 画面の決まりごと

- 利用者や取り込みファイル由来の文字列は `textContent` で入れる。`innerHTML` は使わない。
- アイコンはインライン SVG(`<symbol>` を定義し `<use>` で参照。Material Icons、Apache 2.0)。絵文字を UI に使わない。
- 色・余白・角丸・文字サイズは `:root` の CSS 変数に集約。テーマは `html[data-theme="light"|"dark"]` で変数を上書きし、初期値は `prefers-color-scheme`。
- 拡縮は `:root` の `--zoom` を全サイズ変数に掛ける(設定 `zoom` 50〜200、刻み 10、既定 100)。
- 太字(`font-weight` 600 以上)は使わない。強調は大きさと色で行う。
- UI 文字列は日英の辞書から出す。静的な文字列は `data-i18n`、`aria-label` は `data-i18n-label`。
- 骨格は `height: 100dvh` の縦積み: `header#toolbar` / `main#content`(先頭に `h1#page-title`)/ `footer#status-bar` / `nav#tabbar`。
- タップ対象は 44px 以上。`input` / `select` / `textarea` は `font-size: max(16px, …)`。
- 入力と編集は `dialog#sheet`(下から出るシート)。検証エラーのあいだは OK ボタンを無効にして理由を表示する。開いたときのフォーカスはシートの見出しに置く(iOS で日付ピッカーが勝手に開かないように)。
- ツールバー(右上): ヘルプ、ダーク/ライト、縮小、拡大、日英。無操作 10 秒で薄くなる。ヘルプは system-support のマニュアルを別タブで開く。
- ステータス帯(下部): 機器と記録の件数、直近の操作結果(「保存しました」「3 件を読み込みました」など)、状態ドット(緑 = 正常 / 黄 = 注意 / 赤 = 失敗)。
- PWA: `display: standalone`、`start_url` / `scope` は `./`、`theme-color`、`apple-mobile-web-app-*` メタ。

## 5. データ

### 5.1 保存先

| 置き場所 | 中身 |
|---|---|
| localStorage `mmnote` | `{ version: 1, settings }` |
| IndexedDB `mmnote`(version 1) | 下の 4 ストア |

| ストア | キー | インデックス | 中身 |
|---|---|---|---|
| `equipment` | `id` | なし | 機器 |
| `records` | `id` | `equipmentId` | メンテナンス記録 |
| `photos` | `id` | `ownerId` | 写真本体(JPEG の Blob)と属性 |
| `thumbs` | `id`(写真と同じ) | なし | サムネイル(JPEG の Blob) |

起動時に `equipment` と `records` を全件メモリに読み、描画はメモリ上のデータから行う。サムネイルは表示するときに読む。写真本体は拡大表示とエクスポートのときだけ読む。

起動時に `navigator.storage.persist()` を呼ぶ(使えない・拒否された場合は何もしない)。

### 5.2 機器

| 項目 | 型 | 備考 |
|---|---|---|
| `id` | string | `crypto.randomUUID()` |
| `name` | string | 必須、1〜60 字 |
| `category` | `vehicle` / `machine` / `facility` / `other` | 既定 `other` |
| `maker` | string | 任意 |
| `model` | string | 型番。任意 |
| `serial` | string | 製造番号。任意 |
| `acquiredOn` | `YYYY-MM-DD` / null | 導入日 |
| `specs` | `{ label, value }[]` | 自由に行を足す。最大 30 行 |
| `note` | string | 任意 |
| `photoIds` | string[] | 並び順。先頭が一覧の表紙 |
| `createdAt` / `updatedAt` | ISO 8601 | |

### 5.3 メンテナンス記録

| 項目 | 型 | 備考 |
|---|---|---|
| `id` | string | |
| `equipmentId` | string | 必須 |
| `date` | `YYYY-MM-DD` | 実施日。必須。既定は今日 |
| `kind` | `inspection` / `repair` / `replacement` / `cleaning` / `other` | 区分。既定 `inspection` |
| `title` | string | 作業内容。必須、1〜80 字 |
| `cost` | 整数(0 以上)/ null | 費用 |
| `vendor` | string | 作業者・業者。任意 |
| `meterValue` | 数値(0 以上)/ null | 計器の値 |
| `meterUnit` | string | `km`、`h` など。任意、8 字まで |
| `nextDue` | `YYYY-MM-DD` / null | 次回予定日 |
| `note` | string | 任意 |
| `photoIds` | string[] | |
| `createdAt` / `updatedAt` | ISO 8601 | |

### 5.4 写真

| 項目 | 型 | 備考 |
|---|---|---|
| `id` | string | |
| `ownerType` | `equipment` / `record` | |
| `ownerId` | string | |
| `blob` | Blob | JPEG。長辺 1600px まで縮小、品質 0.85 |
| `width` / `height` | 整数 | 縮小後 |
| `createdAt` | ISO 8601 | |

- 取り込みは `<input type="file" accept="image/*" multiple>`(スマートフォンではカメラか写真ライブラリを選べる)。
- 保存時にサムネイル(長辺 320px、品質 0.7)を作り `thumbs` に入れる。
- 1 つの機器・1 つの記録につき 10 枚まで。
- 読めない画像は取り込まず、ステータス帯で件数を知らせる。
- 機器を消すと、その記録と写真もすべて消す(確認あり)。記録を消すと、その写真も消す。
- 写真は、機器・記録の入力シートの中でも、詳細画面でも追加できる(機器の前で「撮って、書いて、保存」を 1 回で済ませるため)。シートで選んだ写真は保存するまでメモリに持ち、キャンセルすれば捨てる。保存は、本体・写真・サムネイルを 1 つのトランザクションで書く。失敗したらシートを閉じず、選んだ写真も入力内容も残す。

### 5.5 設定

| キー | 値 | 既定 | 備考 |
|---|---|---|---|
| `theme` | `auto` / `light` / `dark` | `auto` | 表示のみ |
| `zoom` | 50〜200(刻み 10) | 100 | 表示のみ |
| `lang` | `ja` / `en` | ブラウザの言語が日本語なら `ja`、それ以外は `en` | 表示のみ |
| `dueSoonDays` | 1〜180 | 30 | 何日前から「期限間近」とするか |
| `currency` | 4 字までの文字列 | `¥` | 費用の前に付ける記号 |

優先順位は URL クエリ > localStorage > 既定値。URL クエリの値は `?save=1` のときだけ保存する。`?tab=` で開くタブを指定できる(保存しない)。

## 6. 次回予定の判定

- 機器ごと・区分ごとに、実施日が最も新しい記録(同日なら `createdAt` が新しいほう)を 1 件選ぶ。その記録に `nextDue` があれば「生きている予定」とする。
  - 同じ区分の新しい記録を書けば、前の予定は自動的に済みになる。
  - 最新の記録に `nextDue` が無ければ、その区分の予定は無い(予定を取り消したいときは、最新の記録の次回予定日を空にする)。
- 状態は今日との比較で決める。
  - `overdue`: `nextDue` < 今日
  - `soon`: 今日 ≦ `nextDue` ≦ 今日 + `dueSoonDays`
  - `later`: それより先
- 機器の一覧に出すバッジは、その機器の生きている予定のうち最も日付が早いもの。
- 記録の入力シートでは、次回予定日の欄の横に「1 か月後 / 3 か月後 / 6 か月後 / 1 年後」のボタンを置き、実施日を起点に日付を埋める(月末は月の最終日に丸める)。
- 日付が変わったら(1 分ごとの確認と、`visibilitychange` での復帰時)表示を更新する。シートが開いているあいだは描画しない。

## 7. 画面

下部タブは 4 つ: 機器 / 予定 / 記録 / 設定。

```
┌──────────────────────┐  ┌──────────────────────┐
│ メンテナンス手帳 ?◐−＋A│  │ ← フォークリフト 2号 ✎│
│ [検索        ] [種別▾]│  │ [写真][写真][＋]     │
│ ┌────┐ 社用車 1号    │  │ ハコベ産機 / HB-15E  │
│ │写真│ 期限切れ 点検  │  │ 次回 ─────────────── │
│ └────┘               │  │  12/02 点検  あと11日│
│ ┌────┐ フォークリフト │  │ 仕様 ─────────────── │

   機器タブ(一覧)            機器の詳細
```

### 7.1 機器タブ

- 一覧: 表紙のサムネイル、名称、メーカー / 型番、予定のバッジ(期限切れ / あと N 日。`later` は出さない)。
- 検索(名称・メーカー・型番・製造番号・メモ・仕様の部分一致)、種別の絞り込み、並べ替え(名称順 / 期限が近い順 / 更新が新しい順)。
- 右下の追加ボタンで機器の入力シート。
- 0 件のときは、追加の案内と「サンプルデータを入れる」への導線を出す。
- タップで詳細へ。詳細は同じタブの中で切り替え、戻るボタンで一覧へ(ブラウザの戻る操作でも一覧に戻る)。

### 7.2 機器の詳細

- 写真の横スクロール(タップで拡大表示。拡大表示に削除と「表紙にする」)、追加ボタン。
- 基本情報、次回予定(生きている予定を日付順)、仕様、メモ、記録の履歴(新しい順)。
- 編集、削除、記録の追加。記録をタップすると記録の詳細(内容、写真、編集、削除)。

### 7.3 予定タブ

- 全機器の生きている予定を日付順に並べる。「期限切れ」「期限間近」「それ以降」の 3 つに区切る。
- 各行: 予定日、機器名、区分、元になった記録の作業内容、残り日数。
- 行をタップするとその機器の詳細へ。行の「実施を記録」ボタンで、機器と区分と作業内容を引き継いだ記録の入力シートを開く。

### 7.4 記録タブ

- 全機器の記録を実施日の新しい順に並べる。月ごとに見出しを入れ、その月の費用の合計を出す。
- 区分と機器での絞り込み、作業内容・業者・メモの検索。
- タップで記録の詳細。

### 7.5 設定タブ

`<details>` のセクションを縦に並べる。

| セクション | 中身 |
|---|---|
| 表示 | テーマ、拡大率、言語、期限間近の日数、通貨記号 |
| データ | エクスポート、インポート、サンプルデータを入れる、全消去、保存量の目安(`navigator.storage.estimate()`) |
| サポート | system-support の公開ページへのリンク |
| About | アプリの説明、バージョン、GitHub リンク、MIT ライセンス、クレジット(fflate、Material Icons) |

### 7.6 サポートのリンク

リンク先は index.html 内の定数 1 か所で持つ(公開リポジトリを見た人が、自分のテナントに差し替える場所が分かるように)。

## 8. エクスポート / インポート

### 8.1 ZIP の中身

ファイル名は `mmnote-YYYYMMDD-HHmm.zip`。

```
data.json
photos/<写真 id>.jpg
```

`data.json`:

```json
{
  "app": "mmnote",
  "version": 1,
  "exportedAt": "2026-11-21T09:00:00.000Z",
  "settings": { },
  "equipment": [ ],
  "records": [ ],
  "photos": [
    { "id": "…", "ownerType": "equipment", "ownerId": "…", "file": "photos/….jpg", "width": 1600, "height": 1200, "createdAt": "…" }
  ]
}
```

- 写真は無圧縮(JPEG は縮まないため)、`data.json` は圧縮して入れる。
- サムネイルは入れない。インポート時に作り直す。

### 8.2 インポート

- ZIP ファイルを選ぶ → 検証 → 件数を示して確認 → 置き換え。インポートは**全置き換え**(今のデータは消える)。確認の文面でそれを明示する。
- 検証は `Logic` の関数で行う。`app` が `mmnote` でない、`version` が未知、`data.json` が無い・読めない場合は中止して理由を表示する。
- 個々のデータは正規化し、不正なもの(必須項目が無い、機器の無い記録、ファイルの無い写真、持ち主の無い写真)は捨てて、捨てた件数を知らせる。
- 書き込みは、検証が全部済んでから行う。途中で失敗したら、今のデータを残す。
- 設定も取り込む(表示のみのキーも含む)。

### 8.3 サンプルデータ

- データが 0 件のときだけ押せる。機器 4 件(車両、フォークリフト、コンプレッサー、エアコンなど)と記録 15 件前後。期限切れ・期限間近・それ以降が 1 件以上ずつ出るよう、日付は「今日」からの相対で作る。
- 写真は外部ファイルに頼らず、コード内の SVG の絵を JPEG にして、通常の写真と同じ経路で保存する。
- 文言は現在の言語で作る。

### 8.4 全消去

確認のうえ IndexedDB の全ストアと localStorage `mmnote` を消し、初期状態に戻す。

## 9. エラーの扱い

- IndexedDB が開けない(プライベートブラウズなど): 画面に理由を出し、状態ドットを赤にする。入力はさせない。
- 保存の失敗(容量超過など): シートを閉じず、理由を表示する。入力内容は残す。
- 画像の読み込み失敗: その画像だけ飛ばし、件数を知らせる。
- ZIP の読み込み失敗: 中止し、今のデータは変えない。
- iOS では、ホーム画面のアプリとブラウザで保存領域が別。ブラウザで長く開かないとデータが消されることがある。データのセクションに、定期的なエクスポートを勧める一文を置く。

## 10. テスト

- `test/*.test.mjs` に `Logic` のテストを書く。Node.js 20 以上、追加ツールなし(`node --test test/*.test.mjs`)。ネットワークに依存させない。
- 実装はテストを先に書く(TDD)。
- 対象: 設定のマージと検証、URL クエリの解釈、機器・記録の検証と正規化、期限の判定(境界: 当日、`dueSoonDays` ちょうど、月末、同日の記録が複数)、「N か月後」の計算、絞り込みと並べ替え、月ごとの集計、エクスポート用オブジェクト、インポートの検証(不正データの除外と件数)、i18n(日英で同じキーがそろっていること)、サンプルデータ(正規化を通ること、3 つの状態が出ること)。
- IndexedDB、画像の縮小、ZIP の読み書き、画面の操作は、ブラウザで実際に動かして確認する(スマートフォン幅で、機器の登録 → 写真 → 記録 → 予定 → エクスポート → 全消去 → インポートの一巡)。
